# Contributing to Iris

Short version of how a change gets into `main`. The full process is in
[docs/05-process/how-we-work.md](docs/05-process/how-we-work.md); the checks are described in the
[README](README.md) ("Commit hooks", "Pull requests", "Continuous Integration").

## Before you start

- Every change belongs to a GitHub issue with an ID: `US-` (story), `T-` (task), `SET-` (setup),
  `FIX-` (fix) or `ES-` (epic).
- Enable the commit hooks once per clone: `git config --local core.hooksPath .githooks`.
- Name the branch after the issue: `<ID>-short-description`, for example
  `FIX-34-contributor-docs-bypass-and-ai-tools`.

## Commits

- Subject: `<ID> <type>(<scope>): <summary>`, for example `US-17 feat(households): add the members step`.
  Types: `feat`, `fix`, `docs`, `test`, `refactor`, `chore`, `ci`. The scope starts with a lowercase
  letter and holds only lowercase letters, digits and hyphens (`user-profile`, not `user_profile`).
  The `commit-msg` hook and the `commit-policy` check enforce it.
- Every source file you add or change starts with its AI contribution line: `No substantial AI-generated code`,
  `Below 50% AI-generated` or `50% or more AI-generated`. Code first generated by AI stays AI-generated
  after you edit it.

## Pull requests

To open a pull request, use the `create-pr` agent skill: in Claude Code, type `/create-pr`.
It merges the target branch into yours, runs the checks, writes the description from the
PR template and checks it against the PR policy before opening the PR. See
[docs/guides/create-pr.md](docs/guides/create-pr.md) for what it asks, how it behaves and
the one-time setup (`gh`, the `project` scope, repository access).

If you open one by hand, follow [.github/pull_request_template.md](.github/pull_request_template.md):

- Title `[PR] <ID>: <summary>`.
- `Closes #<issue>` for a pull request into `main`; `Part of #<issue>` into a story branch.
- The tests you added, including an error or edge case, or a line starting with `No tests:` and the reason.
- One AI contribution level and the list of AI-assisted files. For a feature or fix built with AI help, add
  an entry to the wiki's [AI Usage](https://github.com/B-A-D-R-SL/iris/wiki/AI-Usage) page for the issue's
  iteration. `AI_USAGE.md` lists the AI tools and points to the wiki; never add entries to it.

## Review and merge

- At least one teammate reviews against the [review rules](docs/05-process/review-rules.md) and approves.
  The approval says what was checked. CodeRabbit's approval does not count as that review.
- The `main` ruleset requires four checks (`backend`, `frontend`, `pr-policy`, `commit-policy`), the
  teammate's approval after the last push, and resolved review threads.
- Merge with a merge commit. Squash and rebase merging are turned off.
- **Admin bypass.** Repository admins (listed on the wiki's
  [Repository Access](https://github.com/B-A-D-R-SL/iris/wiki/Repository-Access) page) can bypass the
  ruleset, but only when merging a pull request. Use it only when a check fails by design or for a cause
  outside the pull request. Never use it to skip the teammate's review. Post the reason as a comment on
  the pull request before merging. Example: [#741](https://github.com/B-A-D-R-SL/iris/pull/741), where
  `pr-policy` fails on purpose because any change to `AI_USAGE.md` fails it.
